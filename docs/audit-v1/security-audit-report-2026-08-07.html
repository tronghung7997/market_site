2 — Kiến Trúc & Attack Surface
Internet │ ├── :3001 ──► Next.js 16.3.0 (frontend) │ │ /api/[...path] proxy ──► marketplace-svc:8001 │ └── :8001 ──► FastAPI marketplace-svc ◄── EXPOSED PUBLIC, không TLS proxy │ [market_site bridge network] ├── postgres:5432 (port không public) └── redis:6379 (no auth, port không public) Cloudflare Tunnel token: committed vào git (đã comment nhưng còn trong history) Private registry: registry.k7:5000 (HTTP plaintext, không digest pinning)
⚠ Port 8001 public bypasses toàn bộ proxy controls: CSRF check, header stripping, internal/ blocklist, cookie-only auth model. Kẻ tấn công gọi thẳng :8001 với JWT giả mạo (từ JWT_SECRET bị lộ) có toàn quyền admin. Redis không auth — mọi process trong Docker network đọc/ghi được kể cả rate-limit counters.
3 — Critical Findings
9 findings · CVSS 8.1–9.8
C-1
Working admin account seeded vào production database
CVSS 9.8 OWASP A07 docker-compose.yml:18 → db/marketplace-seed.sql:1006
Seed file mount vào production compose, chạy tự động khi init volume mới. Tạo tài khoản admin@dxtrade.example.com / DemoPass123! với roles [buyer, admin, seller]. Account ID 1 đồng thời là platform fee wallet — mọi người có repo access đều biết thông tin đăng nhập này.
Fix: Xóa seed mount khỏi production compose. Chạy python -m src.ops.purge_demo. Thêm startup assertion từ chối *@dxtrade.example.com trên production.
C-2
Live production secrets committed vào git history
CVSS 9.1 OWASP A02 docker-compose.yml:11,39,41,42
4 secrets production nằm plaintext trong file được track bởi git: POSTGRES_PASSWORD, DATABASE_URL, JWT_SECRET (HS256 signing key), INTERNAL_API_KEY. Cloudflare TUNNEL_TOKEN đã comment nhưng còn nguyên trong git history. Bất kỳ ai có repo access có thể forge JWT với roles: ["admin"] → toàn quyền admin. Chain với C-FE-2 cho phép unauthenticated access vào /internal/* từ internet.
Fix: Rotate ngay 4 secrets (JWT rotation invalidates tất cả sessions hiện tại). Purge git history (git filter-repo). git rm --cached docker-compose.yml. Thêm gitleaks vào Jenkinsfile blocking stage.
C-3
Negative quantity mints unlimited wallet balance
CVSS 9.3 OWASP A04 src/orders/schemas.py:8 · src/wallet/service.py:93
Field quantity: int = 1 không có constraint ge=1. Buyer đặt quantity=-100 → total âm → kiểm tra wallet.available_balance < amount (ví dụ: 0 < -500000) trả False → pass qua → available_balance -= -500000 → cộng vào tài khoản. Buyer có thể tạo số dư tùy ý, rút ra ngay.
Fix: quantity: int = Field(1, ge=1, le=100). Guard if amount <= 0: raise trong tất cả wallet mutators.
C-4
Wallet race condition — double-spend / double-pay seller
CVSS 8.6 OWASP A04 src/wallet/service.py:91 · src/orders/service.py:441
Không có FOR UPDATE lock ở bất kỳ đâu trong wallet service. N concurrent requests đều pass balance check với giá trị stale, tất cả deduct từ cùng 1 row → balance âm. confirm_order tương tự: 2 request đồng thời đều read trạng thái delivered, đều gọi release_escrow → seller được credit 2 lần, buyer debit 1 lần. Dễ trigger bằng double-click hoặc script.
Fix: .with_for_update() trong deduct_credit, request_withdraw, confirm_order, tất cả dispute/withdrawal approval. Thêm CHECK (available_balance >= 0) qua Alembic làm backstop.
BE-C-1
Negative units trên usage charge → unlimited free gateway quota
CVSS 8.6 OWASP A04/A01 src/usage/schemas.py:8 · src/usage/service.py:87
Field units: int = 1 không có ge=1. Buyer set units=-1000000 → units_remaining trở thành effectively unlimited → hammers /gw/{key}/<endpoint> miễn phí. Mỗi request forwarded là real, billed request đến backend của seller.
Fix: units: int = Field(1, ge=1) trên cả hai request models. Guard if units < 1: raise HTTPException(422) đầu charge_usage().
BE-C-2
Seller-settable negative variant price → mint wallet balance
CVSS 9.1 OWASP A04/A08 src/products/schemas.py:61 · src/orders/service.py:56
Field price: int không có ge=0. Seller tạo variant price=-50,000,000, buyer mua → wallet buyer được cộng thêm 50 triệu VND, có thể rút ngay. Đây là path riêng biệt với C-3 — fix C-3 không đóng được lỗ hổng này.
Fix: price: int = Field(ge=0) trên VariantCreate/Update. CheckConstraint("price >= 0") trên DB table.
FE-C-1
Live secrets committed vào git (duplicate với C-2 — xác nhận từ frontend audit)
CVSS 9.8 OWASP A02 docker-compose.yml:11,39–42
Frontend deep audit xác nhận độc lập: JWT_SECRET trong git cho phép forge admin JWT. INTERNAL_API_KEY chain với FE-C-2 (path traversal) → unauthenticated access /internal/usage/charge, /internal/resources/acquire, /internal/ops/purge-demo-accounts từ public internet.
Fix: Cùng với C-2. Ưu tiên thực hiện ngay.
FE-C-2
API proxy internal/ blocklist bypass qua path traversal
CVSS 9.1 OWASP A01 frontend/app/api/[...path]/route.ts:59
Blocklist validate raw string trước khi new URL() normalize. Các path như "../internal/foo", "a/../../internal/z" đều bypass guard nhưng sau normalize trỏ vào /internal/*. Chain với FE-C-1 (leaked key) và FE-H-1 (proxy forward header): curl "/api/%2e%2e/internal/metrics" -H "X-Internal-Key: 7w8EAM76idmctHxtg1820VIzk7N85nDU".
Fix: Validate AFTER normalization. Reject traversal segments (.., ., \0) trước. Chuyển sang allowlist ~40 route prefixes thay vì blocklist.
BE-C-3
confirm_order không có row lock → concurrent confirms double-pay seller
CVSS 8.1 OWASP A04 src/orders/service.py:441
Pattern with_for_update đã tồn tại ở provision_pending_order:384 nhưng không được áp dụng trong confirm_order. Race condition tương tự còn xuất hiện ở disputes/service.py (refund/reject/partial_refund) và wallet/service.py (approve/reject withdrawal).
Fix: await db.get(Order, order_id, with_for_update=True) trong confirm_order và tất cả dispute/withdrawal approval paths. Thêm UNIQUE(reference_id, type) partial index trên transactions làm ledger backstop.

6 — Điểm Bảo Mật Tốt (Giữ Nguyên)
Startup config validation từ chối insecure secrets, enforce ≥32-byte entropy
SSRF guard DNS-pinning, re-validate mỗi outbound call, trust_env=False
PayOS webhook: compare_digest, empty-key refusal, FOR UPDATE, idempotency, reject negative amount
Provider webhook fail closed — không configured secret → reject mọi callback
httpOnly + sameSite:strict + secure cookie; không token trong localStorage
CSRF qua Fetch-Metadata với Origin fallback
Auth dependency coverage đầy đủ ~20 routers
Gateway path traversal blocked: ^[A-Za-z0-9_-]{1,64}$ + endpoint allowlist
Auth rate limiting bucketed theo cả IP và hashed email; fail_open=False
Sentry scrubbing: send_default_pii=False, drop body/query/cookies
Provider credentials encrypted at rest với Fernet; selective field encryption
Tất cả SQL parameterized — không có string-concatenated queries
Zero XSS sinks frontend: không dangerouslySetInnerHTML, eval, innerHTML
Token không expose JavaScript — httpOnly cookie only (BFF pattern)
Seller markdown sandboxed: disableParsingRawHTML: true
npm audit = 0 vulnerabilities · pip-audit = 0 vulnerabilities
