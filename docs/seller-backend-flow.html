Luồng backend seller và tính giá

Seller chỉ cung cấp cấu hình kết nối. Platform mã hoá credential, tính giá, giữ tiền ký quỹ và gọi upstream thay buyer.

1. Seller đăng ký và được duyệt backend

flowchart TD
  S[Seller: Đăng ký backend] --> F[Nhập tên + loại kết nối<br/>Base URL + API key<br/>endpoint map/webhook secret]
  F --> V{Hợp lệ?}
  V -- Không --> E1[Hiện lỗi cấu hình / URL không an toàn]
  V -- Có --> ENC[Mã hoá credential khi lưu]
  ENC --> P[Provider: pending_review]
  P --> ST[Seller tự test kết nối]
  P --> Q[Admin: hàng đợi duyệt]
  Q --> T[Review: cấu hình + test + ghi chú]
  T --> HT{Kết quả test}
  HT -- Unhealthy --> R[Từ chối + bắt buộc ghi lý do]
  HT -- Probe skipped --> A{Admin xác nhận<br/>đã kiểm tra thủ công}
  A -- Chưa --> Q
  A -- Rồi --> AP[Duyệt]
  HT -- Healthy --> AP
  R --> FIX[Seller sửa cấu hình]
  FIX --> P
  AP --> READY[Provider: approved]
  READY --> ATTACH[Seller gắn provider vào sản phẩm]
  ATTACH --> COMPAT{Adapter tương thích<br/>pricing strategy?}
  COMPAT -- Không --> E2[Chặn lưu]
  COMPAT -- Có --> LIVE[Sản phẩm sẵn sàng bán]

2. Buyer tính giá, tạo đơn và platform gọi backend

flowchart TD
  B[Buyer mở sản phẩm] --> C[Nhập cấu hình yêu cầu]
  C --> Q[Pricing engine: quote_product]
  Q --> RP[resolve_pricing: strategy + params]
  RP --> VAL{Validate input}
  VAL -- Sai --> ERR[400: cấu hình không hợp lệ]
  VAL -- Đúng --> CALC[Strategy.quote: amount + quantity]
  CALC --> LIMIT{Có vượt giới hạn<br/>adapter?}
  LIMIT -- Có --> EQL[Chặn trước khi trừ ví]
  LIMIT -- Không --> ORDER[Tạo order: pending]
  ORDER --> ESCROW[Trừ credit vào ký quỹ]
  ESCROW --> AD[Adapter factory: lấy provider]
  AD --> MATCH{Provider và pricing<br/>strategy tương thích?}
  MATCH -- Không --> REF1[Huỷ đơn + hoàn tiền]
  MATCH -- Có --> NET{Adapter gọi network?}
  NET -- DB/local --> INLINE[Provision inline]
  NET -- Upstream API --> BG[Commit pending + chạy nền]
  INLINE --> RES{Kết quả provision}
  BG --> LOCK[Lock order + Idempotency-Key]
  LOCK --> UP[Platform gọi upstream<br/>bằng credential seller]
  UP --> RES
  RES -- Delivered --> OK[Đơn đã giao]
  RES -- Processing/task --> PROC[Đơn đang xử lý]
  RES -- Lỗi/không rõ --> PEND[Giữ pending để sweeper retry]
  PEND --> DEAD{Quá deadline?}
  DEAD -- Chưa --> LOCK
  DEAD -- Rồi --> REF2[Huỷ đơn + hoàn tiền]

Nguyên tắc tính tiền

user_config → validate → quote(params, user_config) → amount + quantity. Ví buyer chỉ bị trừ một lần theo amount từ quote; nếu cấu hình/provider không hợp lệ thì đơn bị chặn hoặc hoàn tiền.
